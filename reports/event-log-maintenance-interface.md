# EARLY integration choice: ordinary kernel flock, held by inherited directory FD

Source-verified additional canonical mutator: **server/projectsMigrate.ts** (`migrateProjects` rewrites/moves event files, `migrateBack` restores originals), invoked by **server/projectsCli.ts**, outside this worker's convlog ownership. Therefore primary-service cgroup observations alone are NOT proof that every mutator is excluded. Rust BoxSync deliberately excludes `.vault-chat/events`; normal engine/worker canonical appends go through ConvLog.emit. Importer/piSession produce native session files, not independent canonical root-event appenders.

There is no installed fs-ext/proper-lockfile/flock Node binding, and Node v22 has no fs.flockSync. No custom PID lease is needed: Linux **util-linux flock descriptor mode** locks an inherited directory FD. Open the events directory in Node, spawn `flock --shared --nonblock 3` ONCE with that FD inherited as child FD 3, and retain the original FD for the ConvLog's lifetime. Kernel flock ownership follows the shared open-file description, so child exit does NOT release the parent's lock. Verified synthetic OS test: shared acquire=0; separate exclusive while parent FD open=1; exclusive after close=0. No process per event and no long-lived lock-holder daemon/registry/file. Crash closes FD automatically.

Implemented this in `server/convlog/maintenance.ts` plus ConvLog ownership. Offline compactor can import `acquireEventDirectory(dir,"exclusive")`, which returns an idempotent release callback, and hold it from BEFORE source inspection through backup/verification/atomic replacement/directory fsync. Directory inode must never be rotated. Startup uses shared mode before epoch/heal/reserve/checkpoint; constructor error releases, ordinary process lifetime retains. Explicit closed ConvLog cannot write.

**Parent action required outside my ownership:** make the existing projects migration/back CLI acquire EXCLUSIVE locks on ALL affected existing event directories before reading/changing them, in stable sorted order, release in finally. Do not claim apply-safe before this is integrated. Shell/manual tools that ignore advisory flock are outside the protocol and must be excluded by operator maintenance rules; no lock can constrain arbitrary same-user mutation.

Checkpoint contract (implemented in my branch; `checkpointFor(candidateFile,picture,offset,completePointedIndex)` is the owner-exported builder): `LogCheckpoint` exported by `server/convlog/log.ts`: `{v:3,rv:REDUCER_VERSION,seq,picture,position,pointed?}`; `position(file,offset,seq)` exported by `server/convlog/reader.ts` returns `{v:1,dev,ino,birthtimeMs,offset,seq}`. For a compacted replacement at EOF, build identity from the actual same-filesystem candidate inode BEFORE rename (rename preserves inode/birthtime) and use candidate byte length as offset. `pointed` must contain every original pi entry ID grouped under original feed-relative/native session path, preserving overrides in canonical event records.

Cohort replacement safety: exclusive lock excludes runtime. Atomic rename log first, checkpoint second, then fsync events directory; a crash between leaves old checkpoint identity that **new runtime rejects fail-closed**, never uses with new log and never replays an unbounded prefix. Prepare/fsync both temporary files BEFORE either rename. Interrupted apply must be retriable/recoverable from verified backup/retained candidate metadata under exclusive lock; do not claim rollback-free two-file atomicity. Missing/mismatched large checkpoint fails actionable, no data loss or auto-repair. A crash after both renames loads the new cohort. v2 checkpoint is not a substitute for a complete pointer index.
