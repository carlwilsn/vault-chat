# /share — post a vault-chat update

The user runs this **passively** — small build-in-public posts after we finish something, not launch announcements. Match that energy. You drive the workflow; the user supplies the editorial taste (what's worth sharing, final wording).

## Default flow: Bluesky only

`/share` with no flags posts to **Bluesky only**. The user adds `--reddit` explicitly when they want a Reddit post — Reddit is a separate, slower, audience-building play, not the default cadence.

## Voice

**Bluesky default: build-in-public progress voice.**

- Lowercase, casual, no marketing copy, no exclamation points.
- "shipped X today" / "added Y this week" / "the weird thing about X is…" — dev journal, not press release.
- Honest about it being in-progress. Don't say "vault-chat now supports…" like it's a stable shipped product. Say "added voice mode to vault-chat this week" — first-person, in-flight.
- One specific observation > a feature list. The reader doesn't want bullets; they want a thought.
- End with the repo URL on its own line. URLs auto-linkify via facets.

**Reddit (when `--reddit` is used): plain prose, conversational, no markdown formatting.**

- No bold, no headers, no bullet lists. Reddit's audience reads marketing-formatted posts as astroturf, especially in indie subs.
- First-person from the builder's own account. "Hey, been building X for a few months and figured I'd show it."
- End with a soft "would love to hear thoughts" — not an engagement-bait question.
- Disclose if the subreddit rules require it (most indie subs do). Frame as "I built this" up top.

Tone may shift later (user mentioned they may pivot voice down the road). If they say so in-session, follow that for this run; do not edit this file unless asked.

## Workflow

1. **Infer the share from recent conversation.** If the user just invoked `/share` after we finished building/shipping/discussing something, that *is* the share — don't ask "what's the share?" Look at what we just did. Examples:
   - We just shipped a feature → that feature is the share.
   - We just had an insight (e.g. the voice-mode "which questions get asked" framing) → that insight is the share.
   - We just merged a release tag → the release is the share.
   - If context is genuinely ambiguous (e.g. fresh chat, user types `/share` with no preceding work), then ask.
2. **Pull supporting context** if needed:
   - Latest release tag: `git describe --tags --abbrev=0`
   - Commit range since prior tag: `git log <prev>..<latest> --oneline`
   - Release URL: `https://github.com/carlwilsn/vault-chat/releases/tag/<tag>`
3. **Draft for Bluesky** (and Reddit only if `--reddit` was passed). Bluesky posts are ≤290 chars, one post, no threads. URLs auto-linkify via facets so just paste them in plaintext.
4. **Show the draft.** User edits or approves. Iterate freely.
5. **On approval, post:**
   - Bluesky: `node .claude/skills/share/post_bluesky.mjs --text "..."`
   - Reddit (text): `node .claude/skills/share/post_reddit.mjs --subreddit X --title "..." --body "..."`
   - Reddit (link): `node .claude/skills/share/post_reddit.mjs --subreddit X --title "..." --url "..."`
   - Each prints JSON on success: `{platform, url, ts, ...}`. Non-zero exit + stderr on failure.
6. **Append to `devlog/posts.jsonl`** at the repo root, one JSON object per line: `{ts, platform, subreddit?, url, text}`. Create the file/dir if missing.
7. **Report the live URL back.** Don't editorialize about engagement metrics — the user can read those themselves.

## Reddit-specific guidance (only when `--reddit` is used)

- Title ≤ 100 chars, descriptive, no clickbait.
- Pick at most ONE subreddit per run. Cross-posting too fast looks like spam.
- Subreddit fit:
  - **r/SideProject** — softest landing, low gatekeeping, audience is mostly fellow builders.
  - **r/SelfHosted** — desktop app + local files angle.
  - **r/LocalLLaMA** — model-agnostic + voice mode angle. May have karma gates.
  - **r/ObsidianMD** — DO NOT post here unprompted. Sub rules ban first-post promo and AI-generated content; user needs months of organic comment history first. Only draft for this sub if user explicitly confirms they've built that history.
- Check each subreddit's pinned rules before drafting. Some require flair.

## Setup

If a script fails with `Credentials not found at ~/.config/vault-chat-share/credentials.env`, point the user at `.claude/skills/share/SETUP.md`. Do not try to create or guess credentials.

## Out of scope (v1)

- X / Twitter (paid API)
- Scheduled posts
- Image / video uploads
- Auto-trigger on release tags (intentionally manual — user is the editorial filter)

If the user asks for any of the above, flag the gap and ask before doing anything else.
