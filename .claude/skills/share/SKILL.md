# /share — post a vault-chat update

You drive the workflow. The user supplies the editorial taste (what's worth sharing, final wording); you handle the drafting, API calls, and logging.

## Voice (current default: product third-person)

- "vault-chat now supports voice mode…" not "I just added voice mode…"
- Concrete and specific. No marketing fluff, no exclamation points, no "excited to announce".
- Lead with what changed, then who it's for, then a link.
- The user said voice may shift to first-person later. If they say so in-session, follow that for this run; do not edit this file unless they ask.

## Platform rules

**Bluesky** (`post_bluesky.mjs`)
- Hard limit: 300 graphemes. Aim for ≤ 290 to leave headroom.
- One post, no threads in v1. If the idea doesn't fit, tighten it — don't split.
- Always include the release URL (or relevant link) as the final element. URLs auto-linkify via facets in the script.

**Reddit** (`post_reddit.mjs`)
- Title ≤ 100 chars. Descriptive, not clickbait.
- Body is long-form markdown. Cover: what it is, what's new (if a release), one concrete example of the feature in use, link to the latest release.
- Disclose self-promo if the subreddit rules require it (most indie subs do).
- Subreddit-pick guidance:
  - **r/ObsidianMD** — lead with "any folder is a vault" + the markdown angle. Mention git-backed history.
  - **r/LocalLLaMA** — lead with model-agnosticism + OpenRouter. Voice mode is a strong hook here (agent-driving voice is rare).
  - **r/SideProject** — looser self-promo; just frame as an indie tool with a quick demo.
  - **r/SelfHosted** — stress desktop app + local files + no cloud lock-in.
- Pick at most ONE subreddit per `/share` run unless the user explicitly asks for multiple. Cross-posting too fast is the fastest way to look like spam.

## Workflow

1. **Ask** the user what the share is:
   - "Release" → grab the latest tag and commit range
   - "Feature" → ask for a one-sentence pitch
   - "Thought / general update" → ask for the gist
2. **Pull context** as needed:
   - Latest release tag: `git -C <repo> describe --tags --abbrev=0`
   - Commit range since prior tag: `git -C <repo> log <prev>..<latest> --oneline`
   - Release URL: `https://github.com/carlwilsn/vault-chat/releases/tag/<tag>`
3. **Draft** the post(s) for the platforms the user wants. Default to **both** Bluesky and Reddit unless the user specifies. For Reddit, suggest one subreddit and explain why.
4. **Show drafts to the user** with clear labels (`BLUESKY:` / `REDDIT (r/X):`). Ask for edits or approval. Re-draft if needed.
5. **On approval, post:**
   - Bluesky: `node .claude/skills/share/post_bluesky.mjs --text "..."`
   - Reddit (text post): `node .claude/skills/share/post_reddit.mjs --subreddit X --title "..." --body "..."`
   - Reddit (link post): `node .claude/skills/share/post_reddit.mjs --subreddit X --title "..." --url "..."`
   - Each script prints JSON to stdout with `{platform, url, ts}` on success, or exits non-zero with a stderr message on failure.
6. **Append to `devlog/posts.jsonl`** at the repo root. One JSON object per line: `{ts, platform, subreddit?, url, text}`. Create the file/dir if missing. The scripts do NOT do this themselves; you do it after collecting their stdout.
7. **Report back** with the live URLs. Suggest committing `devlog/posts.jsonl` so the share record stays in git.

## Setup (one-time, user's job before first run)

If a script fails with `Credentials not found at ~/.config/vault-chat-share/credentials.env`, point the user at `.claude/skills/share/SETUP.md`. Do not try to create or guess credentials.

## What this skill does NOT do

- Cross-post to X (paid API, deliberately excluded for now)
- Schedule posts (post-now only)
- Upload images or video (text + URL only in v1)
- Auto-trigger on release tags (intentionally manual)

If the user asks for any of the above, flag the gap and ask if they want it added before doing anything else.
